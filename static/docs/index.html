doc-anonymiser documentation

doc-anonymiser replaces sensitive values in your documents with stable placeholders, so a document can be shared, sent to a supplier or given to another tool without exposing who or what it is about. Everything happens on this machine.

What the application does

You import documents, tell the application what counts as sensitive, review what it proposes to replace, and export anonymised copies. Two rules hold at every step.

Your originals are never modified. Imported files are read once, into memory. Nothing is ever written back to the file you picked. Anonymised copies are written only where you choose to save them, through an ordinary save dialog.

Nothing is replaced without your approval. Everything the application finds on its own goes onto a review list first. A suggestion becomes a replacement only after you accept it.

Which files you can import

Plain text (.txt), comma separated values (.csv), Markdown (.md), Word (.docx), PowerPoint (.pptx), Excel (.xlsx) and PDF (.pdf). Any other file is refused with a message saying so, whether you pick it in the dialog or drop it on the window.

On import each document is converted to a common working form so that one anonymisation engine can handle all of them. Spreadsheets are handled per sheet: a simple sheet with a header row keeps its grid and can be exported back to CSV, while a sheet with merged cells or several tables is converted to a structured text form instead.

PDF support is experimental and labelled as such in the import list. Text is extracted page by page, and the result can be imperfect on documents with unusual layouts, so read the preview before relying on it. A PDF that is a scan, with no text layer at all, is refused: converting it would need optical character recognition, which this application does not do.

The five steps

The workflow banner under the menu shows where you are. A step you cannot reach yet is greyed out, for example Export before a run has produced results.

1. Import
Add the documents. Drag them onto the window or use the Add files button. The right hand pane previews the working form of whichever document you select, which is what the anonymisation will actually see. Drag the divider between the two panes to resize them.
2. Configure
Choose what counts as sensitive. Start from a preset (Soft, Standard or Thorough), then adjust the individual checkboxes if you need to. Changing any checkbox switches the preset display to Custom, which simply means the selection is now your own. The same screen holds the list of terms that must never be anonymised, and the settings for the optional local AI.
3. Values
Tell the application which specific values to replace, such as a client name or a person. You can type them in yourself, or use one of the discovery methods to get suggestions. Every suggestion lands on the review list, where you accept or reject it one by one or in bulk. Each accepted value can be expanded to show its variants, the other spellings that will also be replaced, and you can add your own or move one variant to a different value.
4. Run
Run the anonymisation and read the result next to the original. Replacements are highlighted, and hovering one shows the value it replaced. If something was missed, add it here and re-run the fast deterministic passes without starting over.
5. Export
Save the anonymised copies, one at a time or all of them in one zip file. Word, PowerPoint and Excel documents can also be saved in their original format, as a new file. Document properties such as the author and the title are shown for review before that copy is written, since they carry names too.

How values are found

Three mechanisms work together, in this order.

Predefined patterns

Some information always looks the same, so it can be recognised without any guessing: email addresses, phone numbers, web addresses, bank account numbers, value added tax numbers, national identification numbers, payment card numbers, network addresses and more. Where a number carries a check digit, for example a payment card, the check is verified so that an ordinary long number is not mistaken for one. These patterns need no AI and no network connection.

Values you list

The names of clients, projects, internal teams and people cannot be guessed from their shape, so you provide them in the Values step. Each one is expanded into its variants automatically: initials, the surname on its own, the first name on its own, and hyphen or space spellings. That is why entering "Marie Duval" also replaces "M. Duval" and "Duval".

Discovery

Smart detection reads the selected documents and proposes values based on how they are written, for example a capitalised run of words followed by a company form such as S.A. or GmbH. It works entirely offline. Its settings let you make it stricter when it proposes too much.

Auto-discovery with local AI does the same job with a language model running on this machine, which catches names that no rule describes. It is only available when the local AI is switched on and detected. Every proposal it makes is checked against the document text before you see it, so a name the model invented is dropped rather than shown.

Placeholders and the re-identification key

A replaced value becomes a placeholder of the form [CATEGORY_NUMBER], for example [CLIENT_1], [PERSON_3] or [EMAIL_2]. The numbering is stable for the whole session and shared across all loaded documents, so the same real value is always the same placeholder, in every file. That is what keeps an anonymised set of documents readable: you can still follow who did what, without knowing who they are.

The mapping from placeholder back to the real value is the re-identification key. Anyone holding it can undo the anonymisation completely. It stays in memory unless you deliberately export it, or save a session file, which contains it. Treat either file as being as sensitive as the original documents, and never send it together with the anonymised copies.

Local processing and the optional AI

The application makes no network connection of its own. There is no telemetry, no update check, and no cloud service. All of its assets, including this documentation page, are built into the program file.

The one exception is the optional AI, and it does not leave the machine either. It talks to Ollama, a separate program you install yourself, over 127.0.0.1, the address a computer uses to talk to itself. The address is fixed to that loopback address and only the port number can be changed, so the feature cannot be pointed at a remote server.

If Ollama is not installed or not running, every AI control is disabled and explains why in its tooltip. Nothing else is affected: the patterns, the values you list, smart detection, the run and every export work exactly the same without it.

If something goes wrong

An AI button is greyed out
Either the local AI is switched off, under Configure in the AI and advanced settings tab, or Ollama was not detected on 127.0.0.1. Start Ollama, then use Re-probe on that same tab.
Smart detection proposes far too much
Open the smart detection settings in the Values step and raise the minimum length or the minimum number of occurrences, or switch on the exclusion of common words. Values you never want touched belong in the never anonymise list instead, where they are protected from every pass.
Something was not replaced
Add it on the Run screen and re-run the fast deterministic passes. If it is another spelling of a value you already have, expand that value and add it as a variant, so both spellings map to the same placeholder.
Something was replaced that should not have been
Add it to the never anonymise list under Configure. Terms on that list survive every pass, including the AI ones.
A PDF was refused
It has no text layer, which means it is a scan or an image. Convert it to a text bearing document with another tool first, then import that.
