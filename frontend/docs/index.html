doc-anonymiser documentation

doc-anonymiser replaces sensitive values in your documents with stable placeholders, so a document can be shared, sent to a supplier or given to another tool without exposing who or what it is about. Everything happens on this machine.

What the application does

You import documents, tell the application what counts as sensitive, review what it proposes to replace, and export anonymised copies. Two rules hold at every step.

Your originals are never modified. Imported files are read once, into memory. Nothing is ever written back to the file you picked. Anonymised copies are written only where you choose to save them, through an ordinary save dialog.

Nothing is replaced without your approval. Everything the application finds on its own goes onto a review list first. A suggestion becomes a replacement only after you accept it.

Which files you can import

Plain text (.txt), comma separated values (.csv), Markdown (.md), Word (.docx), PowerPoint (.pptx), Excel (.xlsx) and PDF (.pdf). Any other file is refused with a message saying so, whether you pick it in the dialog or drop it on the window.

On import each document is converted to a common working form so that one anonymisation engine can handle all of them. Spreadsheets are handled per sheet: a simple sheet with a header row keeps its grid and can be exported back to CSV, while a sheet with merged cells or several tables is converted to a structured text form instead.

PDF support is experimental and labelled as such in the import list. Text is extracted page by page, and the result can be imperfect on documents with unusual layouts, so read the preview before relying on it. A PDF that is a scan, with no text layer at all, is refused: converting it would need optical character recognition, which this application does not do.

The four steps

The workflow banner under the menu shows where you are. A step you cannot reach yet is greyed out, for example Export before a run has produced results.

1. Import
Add the documents. Drag them onto the window or use the Add files button. The right hand pane previews the working form of whichever document you select, which is what the anonymisation will actually see. Drag the divider between the two panes to resize them.
2. Identify
One screen with two halves. On the left you choose how the application looks: which detection routes are on, the document country, and a preset (Soft, Standard or Thorough) over the individual category checkboxes. Each section has its own preset row, and a preset changes only that section's checkboxes: pressing Thorough under Built-in patterns never moves a switch under Heuristic discovery. Changing any checkbox switches that section's preset display to Custom, which simply means the selection is now your own. Every control has a small information icon beside it that explains what it does, on hover or with the keyboard.

On the right you review what was found. Suggestions wait for a decision and you accept or reject each one, singly or in bulk; My Values holds the ones you accepted, and you can also type a Value in yourself. The same half holds the never anonymise list, the built-in patterns and your own patterns. A Value can be expanded to show its spellings, the other forms that will also be replaced, and you can add your own or drag one to a different Value.

The Built-in patterns tab is read only. It lists what the signal categories you switched on matched the last time you ran detection, grouped by category, so you can check the categories you chose before anything is anonymised. A category that you switched on and that matched nothing still gets its heading, so you can tell "found nothing" apart from "not switched on". There is nothing to accept there: a built-in pattern is a rule you chose, so its matches are applied without review. To change what it finds, tick or untick the categories on the left and run detection again.

You cannot move on to Anonymise while a Suggestion is still waiting. Walking past one would silently answer "reject" for you.
3. Anonymise
Two tabs over the same document, TEXT and IMAGE. TEXT is the words and IMAGE is the pictures, which the anonymisation itself never touches: see Pictures below.

Run the anonymisation and read the result next to the original. Replacements are highlighted, and hovering one shows the Value it replaced and tints, in the Original pane, every place that Value was taken from: its main text and each of its spellings. Select text in either pane to make it a spelling of an existing Value or a Value of its own. If something was missed, Add missed Value declares it and the fast re-run applies it without starting over; every placeholder already handed out keeps its number.

This step never contacts the local model and runs no detection of its own. Nothing is replaced that you did not accept or declare yourself.
4. Export
Save the anonymised copies, one at a time or all of them in one zip file. Word, PowerPoint and Excel documents can also be saved in their original format, as a new file. Document properties such as the author and the title are shown for review before that copy is written, since they carry names too. That same review states what will happen to the pictures, including when nothing will, so a copy that keeps them all says so before it is written.

How Values are found

A Value is one thing to be replaced, with one placeholder for it and all its spellings. Nothing becomes a Value on its own: everything below either matches a pattern you switched on, or produces a Suggestion you accept.

Built-in patterns

Some information always looks the same, so it can be recognised without any guessing: email addresses, phone numbers, web addresses, bank account numbers, value added tax numbers, national identification numbers, payment card numbers, network addresses and more. These patterns need no AI and no network connection. What they matched is listed on the Built-in patterns tab of the Identify step after you run detection.

Some of these numbers carry a check digit. There are two kinds, and the difference matters. For a payment card the check digit is the only thing separating the number from an ordinary long number, so it is always verified: without it every sixteen digit run in your document would be read as a card. For a bank account number the country code and the grouping already identify the shape, so the check digit only corroborates it. When those digits do not add up the match is still replaced, and the row is marked "Check failed" so you can see it. That is deliberate: a mistyped, partly redacted or made up bank account number is exactly what a template or a draft contains, and it is still worth replacing. If you would rather leave those alone, switch on Only replace when the checksum matches under Built-in patterns on the Identify step. It affects nothing else.

Values you declare

The names of clients, projects, internal teams and people cannot be guessed from their shape, so you provide them on the Identify step. Each one gets its spellings automatically: initials, the surname on its own, the first name on its own, and hyphen or space forms. That is why entering "Marie Duval" also replaces "M. Duval" and "Duval". The moment you edit that list yourself it becomes yours, and the application stops adding to it, so a spelling you delete stays deleted.

Signal-based suggestions

A pattern match can also be EVIDENCE about text written somewhere else. An address like pierre.dupont@tpps.com is being replaced because it is personal data in its own right, and it also says that a person called Pierre Dupont and a company whose name starts "Tpps" are involved. If either is written in any of your documents, outside the address itself, it is suggested for review, with the address shown as the reason.

This is a suggestion and never a replacement, and it is switched separately from the pattern. In Configure, on the "Email addresses" row of "Contact details" under Built-in patterns, the "Signal-based suggestions" button opens what an address can be read as: "Person names" from the part before the @, and "Organisation names" from the domain. Each has its own tick box, so you can keep company names from domains without having "pierre.dupont" read as a person. The tick box at the head of that panel switches all of the readings at once, and the row's own tick box in front of "Email addresses" is a different setting: it is the one that decides whether addresses are anonymised.

Clearing any of them stops those suggestions and nothing else. Email addresses are still anonymised, because that is Built-in patterns and the Email category doing their own job. These readings also keep working with Built-in patterns switched off, because they match their own evidence.

Two suggestions built on the same evidence are shown as RELATED, never merged. Two companies reached through one email domain may genuinely be two different legal entities, and only you can say whether they are the same thing.

Heuristic discovery

This reads the selected documents and suggests Values based on how they are written, for example a capitalised run of words followed by a company form such as S.A. or GmbH. It works entirely offline. Its settings, under Discovery strictness, let you make it stricter when it suggests too much.

Local LLM discovery

A language model running on this machine does the same job, and catches names that no rule describes. It is only available when the route is switched on and Ollama is detected, and switching it on is always your decision. Everything it proposes is checked against the document text before you see it, so a name the model invented is dropped rather than shown. It never runs during the Anonymise step.

When two of these find the same thing, it is ONE suggestion carrying both, not two rows to decide about twice.

Pictures

Anonymising the words is only half of a Word document or a PowerPoint deck. The client logo, the screenshot of the client's own system, the photo of the team: those carry as much as a sentence does. A copy saved in the original format carries every picture out with it unless you decide otherwise, so the IMAGE tab on step 3 is where you decide.

It lists every picture in the selected document with its size, where it appears and what will happen to it. One decision covers every place a picture is used: a logo on five slides is one question, and the row says it appears in five places.

Keep it
Where every picture starts, and what happens if you never open this tab.
Replace with a box
The picture becomes a plain rectangle of the same size carrying a short caption you write, for example "Client logo removed". The original pixels are not in the saved file at all.
Blur
The picture is broken into blocks, each replaced by its own average colour, and then smoothed. That throws the detail away rather than smearing it, which is why it is not a light blur you can read through. It is still not a guarantee: the shape, the colours and the position of what was there stay visible. For anything that must not be recognisable at all, use a box or remove it.
Remove
The picture is taken off the page and its bytes are overwritten inside the file. Both halves matter: a picture still in the file that the page no longer draws is a picture anyone can extract.

An SVG picture cannot be blurred, and the control says why when you hover it: a blur over a drawing leaves every original shape and every original piece of text inside the file, so it would be called anonymising without anonymising anything. A box or a removal works on it.

The tab is offered for Word and PowerPoint documents. For a PDF it says so and there is nothing to do: a PDF is saved by rebuilding it from the anonymised text, so every picture in the original is already gone from the file the application writes. Excel workbooks are not reviewed, and text, CSV and Markdown files have no pictures in them.

Your decisions are saved with a session, and the exported report names every changed picture, where it appeared and what was done to it.

Placeholders and the re-identification key

A replaced value becomes a placeholder of the form [CATEGORY_NUMBER], for example [CLIENT_1], [PERSON_3] or [EMAIL_2]. The numbering is stable for the whole session and shared across all loaded documents, so the same real value is always the same placeholder, in every file. That is what keeps an anonymised set of documents readable: you can still follow who did what, without knowing who they are.

The mapping from placeholder back to the real value is the re-identification key. Anyone holding it can undo the anonymisation completely. It stays in memory unless you deliberately export it, or save a session file, which contains it. Treat either file as being as sensitive as the original documents, and never send it together with the anonymised copies.

Local processing and the optional AI

The application makes no network connection of its own. There is no telemetry, no update check, and no cloud service of any kind. All of its assets, including this documentation page, are built into the program file.

The one exception is the optional AI, and it does not leave the machine either. It talks to Ollama, a separate program you install yourself, over 127.0.0.1, the address a computer uses to talk to itself. The address is fixed to that loopback address and only the port number can be changed, so the feature cannot be pointed at a remote server.

If Ollama is not installed or not running, every AI control is disabled and explains why in its tooltip. Nothing else is affected: the patterns, the Values you declare, built-in patterns, signal-based suggestions, heuristic discovery, the run and every export work exactly the same without it.

Letting Ollama use your GPU

Ollama ships with Vulkan support enabled but ignores integrated GPUs unless you tell it not to, and most business laptops have exactly that. It writes dropping integrated GPU in its own log and runs the model on the processor instead.

On Windows the setting has to reach the Ollama service rather than a terminal window, so it is set with setx OLLAMA_IGPU_ENABLE 1 and then Ollama is quit from the system tray and started again. A variable typed into a shell reaches nothing, which is the mistake that makes people conclude the setting does not work. To confirm it took, open the Ollama server log and look for the GPU listed as inference compute and a line reading offloaded N/N layers to GPU.

On the laptop this was measured on, an Intel Arc integrated GPU, a 15-slide deck scanned about 1.2 times faster and the model found somewhat more than it had on the processor. It is free and it does no harm, but it is a modest improvement rather than a transformation. Scanning fewer pages at a time, or choosing a different model, changes the clock more than this does. Discrete NVIDIA and AMD graphics cards are used automatically and need none of this.

If something goes wrong

A model control is greyed out
Either Local LLM discovery is switched off, on the Identify step in the Local LLM discovery section, or Ollama was not detected on 127.0.0.1. Start Ollama, then use Re-probe in that same section.
Detection suggests far too much
Open Discovery strictness on the Identify step and raise the minimum length or the minimum number of occurrences, or switch on the exclusion of common words. Values you never want touched belong in the never anonymise list instead, where they are protected from every pass.
Something was not replaced
Add it on the Run screen and re-run the fast deterministic passes. If it is another spelling of a value you already have, expand that value and add it as a spelling, so both forms map to the same placeholder.
Something was replaced that should not have been
Add it to the never anonymise list on the Identify step. Terms on that list survive every pass, including the AI ones.
A PDF was refused
It has no text layer, which means it is a scan or an image. Convert it to a text bearing document with another tool first, then import that.
